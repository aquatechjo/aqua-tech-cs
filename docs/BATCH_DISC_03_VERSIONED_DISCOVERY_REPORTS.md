# DISC-03 — Versioned Discovery Reports and Human Review

## الهدف

تحويل أدلة جلسة الاكتشاف الجاهزة إلى تقرير أولي منظم وقابل للتتبع، ثم
إجبار مرور التقرير عبر مراجعة بشرية قبل إغلاق مرحلة الاكتشاف والانتقال إلى
مراجعة النطاق والتسعير.

تأتي هذه الدفعة بعد `DISC-02`: أصبح لدينا سجل محادثة وإجابات مؤكدة وفجوات
واضحة. لم يعد من المنطقي الانتقال مباشرة إلى Proposal؛ لأن التسعير والعرض
يحتاجان تقريرًا داخليًا يمكن تدقيق مصادره وإصداراته واعتماده.

## قرار النطاق

- الذكاء الاصطناعي يصوغ **مسودة** فقط.
- الموظف يحفظ **إصدارًا بشريًا** مستقلًا قبل الإرسال للمراجعة.
- اعتماد التقرير لا ينشئ سعرًا أو عرضًا أو عقدًا أو مشروعًا.
- بعد الاعتماد يصبح الإجراء التالي:
  `مراجعة النطاق وإعداد التسعير`.
- يمكن إنشاء التقرير يدويًا عند عدم تهيئة مزود AI، حتى لا يتوقف المسار
  التشغيلي بسبب تكامل خارجي.

## النطاق المنفذ

### التقرير والإصدارات

- سجل `DiscoveryReport` واحد لكل `IntakeSession`.
- سجل `DiscoveryReportVersion` مستقل لكل توليد أو حفظ.
- لا تُكتب التعديلات فوق الإصدار السابق.
- كل إصدار يحفظ:
  - رقم الإصدار.
  - المصدر: `AI_DRAFT` أو `HUMAN_REVISION`.
  - محتوى التقرير المنظم.
  - Hash المحتوى.
  - Snapshot الأدلة المستخدمة.
  - Hash الأدلة.
  - نسخة Prompt عند استخدام AI.
  - المزود والنموذج ومعرّف الاستجابة عند توفره.
- يستطيع المستخدم معاينة أي إصدار محفوظ من سجل الإصدارات.
- يظهر تحذير Stale عندما تتغير أدلة الجلسة بعد حفظ الإصدار.

### محتوى التقرير

العقد المنظم يتضمن:

- الملخص التنفيذي.
- المشكلة الحالية.
- الوضع الحالي.
- النتائج المطلوبة.
- المنهج المقترح.
- عناصر النطاق.
- مقاييس النجاح.
- القيود.
- المخاطر والأثر والمعالجة.
- الافتراضات.
- الأسئلة المفتوحة.
- الخطوة التالية.

لا يوجد في العقد حقل سعر أو Amount أو التزام زمني نهائي.

### بوابة المراجعة البشرية

حالات التقرير:

`DRAFT → IN_REVIEW → APPROVED`

ومسار التعديل:

`IN_REVIEW → CHANGES_REQUESTED → DRAFT → IN_REVIEW`

- لا يقبل النظام إرسال `AI_DRAFT` مباشرة.
- يجب أن يراجع الموظف الحقول ويحفظ `HUMAN_REVISION`.
- الإرسال أو الاعتماد مرفوض إذا تغير Hash الأدلة.
- تعديل إجابات جلسة قيد مراجعة يعيد التقرير إلى
  `CHANGES_REQUESTED`.
- الاعتماد:
  - يثبت الإصدار الحالي.
  - ينقل جلسة الاكتشاف إلى `COMPLETED`.
  - يلغي رابط العميل المتبقي.
  - يؤهل الـLead.
  - ينقل فرصة `NEW` أو `DISCOVERY` إلى `QUALIFIED`.
  - يضع الإجراء التالي لمراجعة النطاق والتسعير.

## تكامل OpenAI

التوليد يستخدم Responses API وStructured Outputs عبر JSON Schema.

الإعدادات الخادمية:

```text
OPENAI_API_KEY=<server-only secret>
OPENAI_DISCOVERY_MODEL=gpt-5.6-sol
```

`OPENAI_DISCOVERY_MODEL` اختياري، وقيمته الافتراضية في هذه الدفعة
`gpt-5.6-sol`.

قيود التكامل:

- `store: false`.
- حد خرج أقصى 6000 Token.
- مهلة 45 ثانية.
- خمس محاولات في الساعة لكل شركة وجلسة.
- حد أدلة خارجية 120 KiB للعملية الواحدة.
- Structured Output يخضع للتحقق مرة أخرى عبر Zod قبل الحفظ.
- لا يُحفظ المفتاح أو يُرسل إلى المتصفح.
- فشل المزود لا ينشئ Version ناقصًا.
- تغيّر الأدلة أثناء الاتصال يمنع حفظ الاستجابة القديمة.

## تقليل البيانات والأمان

لا تُرسل تلقائيًا:

- اسم جهة الاتصال.
- اسم الشركة.
- البريد.
- الهاتف.
- الرسائل الخام.
- الملخص الداخلي.
- الملاحظات الداخلية.
- استنتاج AI سابق.

يُرسل فقط:

- مسار الخدمة ونوعها.
- نسخة قالب الاكتشاف.
- الإجابات المنظمة ذات المصادر:
  `CUSTOMER_FACT`, `UPLOADED_EVIDENCE`, `APPROVED_DECISION`.
- التجاوزات الموثقة.

قبل التوليد، يؤكد الموظف وجود أساس معتمد للمعالجة عبر مزود خارجي، ويُحفظ
المستخدم والتوقيت في التقرير.

قيم العميل تعامل كبيانات غير موثوقة وليست تعليمات للـModel. Prompt يمنع
اختراع حقائق أو أسعار أو التزامات، ويحوّل عدم اليقين إلى افتراض أو سؤال
مفتوح.

## الصلاحيات

- القراءة:
  `OWNER`, `ADMIN`, `SALES_MANAGER`, `OPERATIONS_MANAGER`.
- التوليد والتحرير والإرسال:
  `OWNER`, `ADMIN`, `SALES_MANAGER`.
- طلب التعديلات والاعتماد:
  `OWNER`, `ADMIN`, `SALES_MANAGER`.
- كل القراءة والكتابة مقيدة بـ`companyId`.
- عمليات إنشاء Version والانتقالات تستخدم Row locks وTransactions.

## سجل النشاط

- `DISCOVERY_REPORT_AI_GENERATED`
- `DISCOVERY_REPORT_VERSION_CREATED`
- `DISCOVERY_REPORT_SUBMITTED`
- `DISCOVERY_REPORT_CHANGES_REQUESTED`
- `DISCOVERY_REPORT_APPROVED`

لا يحتوي Metadata على مفتاح API أو محتوى التقرير أو بيانات الاتصال.

## معيار القبول

يستطيع الموظف المخول فتح تقرير جلسة جاهزة، توليد مسودة AI عند تهيئة
الخادم أو بدء تقرير يدوي، مراجعة الحقول وحفظ إصدار بشري، إرسال الإصدار
للمراجعة، طلب تعديل موثق أو اعتماده. يحافظ النظام على كل إصدار وHash
الأدلة، ويرفض التقرير القديم، ولا يغلق الاكتشاف أو يؤهل الفرصة إلا بعد
اعتماد بشري صريح.
